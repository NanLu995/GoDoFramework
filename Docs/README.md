## 权威顺序

发生冲突时按以下顺序核对，并同步修正文档：

1. 根目录 `AGENTS.md` 中的协作和技术硬约束。
2. 源码、工程配置与已经通过的测试所证明的当前实现。
3. 模块 `USAGE.md` 中的 API、失败语义、生命周期、性能和验证说明。
4. [架构基线](01_架构/架构基线.md)中的跨模块事实，以及[决策日志](00_项目/决策日志.md)中的已确认取舍。
5. 当前开发、模块状态、路线图和设计文档。
6. 研究资料；它们只提供证据和候选方向，不建立需求。

## 文档边界

- `Docs/`：项目状态、架构、设计、工作流和研究。
- `PublicDocs/`：面向框架使用者的公开手册、导航、覆盖清单和站点构建。
- 模块 `USAGE.md`：与源码同目录的模块契约。
- 局部 `README.md`：对应 Demo、工具、验证或发布目录的操作入口。
- `CHANGELOG.md`：已经发布或准备发布的用户可见变化。

内部文档不复制完整 public API 表格。需要精确签名时读取源码和模块 `USAGE.md`。
