# InputService 设计

> 最近核对：2026-09-28

## 1. 问题与目标

业务代码如果直接依赖键盘键值、Godot InputMap 或第三方插件对象，改键、设备切换和后端替换会扩散到角色、UI 和流程代码。

InputService 的目标是：

- 让业务只读取 Move、Look、Confirm 等语义 Action；
- 集中处理当前帧状态、迁移、Context 和设备事实；
- 将连续输入读取与离散命令分派分开；
- 允许 GUIDE 等后端通过 Integration 接入，核心不反向依赖插件；
- 保持主线程采样热路径有界、可诊断且低分配。

## 2. 非目标

- 角色移动、摄像机旋转、连招窗口等玩法规则。
- 本地多人设备分配和分屏输入。
- 格斗指令历史、节奏游戏音频级判定。
- 网络输入预测、录制回放和确定性重演。
- 键帽图标、本地化排版和具体设置界面。
- 统一震动效果系统。

## 3. 已确认方案

### 语义模型与 Frame

- Action、Context 和 Binding 使用稳定、区分大小写的语义 ID。
- 后端初始化后 Action 顺序和类型固定，采样写入预分配缓冲区。
- `InputFrame` 是当前渲染帧的轻量只读句柄，跨帧使用会明确失败。
- 需要跨帧保存时读取值快照，而不是保存 Frame。
- 后端采样完整成功后才原子提交；失败不会覆盖上一帧或推进序号。
- 状态、迁移、持续时间和进度都在核心边界校验，不接受非有限或越界数据。

### Context 所有权

- 基础 Context 表示长期默认输入集合。
- Overlay 与较低层共同生效；Exclusive 屏蔽较低层。
- 临时 Context 使用可释放 Lease 表达所有权，可从栈中任意位置安全释放。
- Context 应用失败时，核心栈和后端映射都保持原状态。
- 旧 Push/Pop API 只用于迁移；新代码使用 Lease，避免异常退出留下 Context。

### 连续输入与离散路由

- 连续移动、视角和当前按压状态直接读取 Frame。
- Confirm、Pause、Interact 等离散迁移由 `IInputActionRouter` 分派。
- 后压入的 Scope 优先；Handler 可以消费当前 Action 或继续向下传播。
- 分派期间的绑定变化延后提交，保持当前遍历稳定。
- Context 或路由变化后，非 Idle Action 必须先回到 Idle，避免仍按住的按键重触发新页面命令。
- Router 只传递输入事实，不再复制为第二套全局输入事件。

### 后端与可选能力

- `IInputBackend` 是 Integration 边界，不是业务 API。
- GUIDE 后端位于 `Integrations/GuideInput/`，核心 Input 不引用它。
- 设备跟踪、提示查询、重绑定和持久化通过显式能力接口暴露。
- 重绑定候选保持后端私有，不把插件资源类型泄漏给业务。
- 保存时机由游戏决定；InputService 不在每次改键后隐式写盘。

## 4. 生命周期、失败与性能

GoDoRuntime 自身按固定顺序执行：

`InputService.Update → InputActionRouter.Dispatch`

读取当前 Frame 的业务节点应在 GoDoRuntime 之后处理；业务若显式设置更早的 `process_priority`，框架不会改写该顺序。

所有服务调用、采样、Context、改键和关闭操作只允许 Godot 主线程。未安装后端、首次采样前读取、未知 Action/Context、过期 Frame、无效路由或后端能力不一致都会明确失败。

热路径使用预分配数组，不执行资源查找、LINQ 或集合创建。Context、绑定和提示查询属于低频路径，可以进行有界分配。具体失败类型、API 契约和基准证据只维护在模块 `USAGE.md`。

Debug 构建提供只读 Frame、Context、Router 和设备快照；Release 不包含诊断快照状态。

## 5. 剩余验证

核心、GUIDE 适配、运行时改键、提示查询、持久化和 Debugger 页面已经有自动回归；既有 Windows 键鼠和手柄验收已完成。提升成熟度前仍需：

- 在真实项目中复核暂停、Modal、场景切换和长按重触发手感；
- 在移动端验证触摸设备类别与后端行为；
- 在非 Windows 平台验证设备切换、拔插和提示文本；
- 根据真实业务决定是否需要独立震动 API。
