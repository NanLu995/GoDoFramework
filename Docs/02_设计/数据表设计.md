# DataTable 设计

> 文档类型：设计
> 状态：验证中
> 权威范围：DataTable 工具链与运行时的设计目标、关键取舍和剩余验证；命令、API 与验证明细以模块 `USAGE.md` 为准
> 最近核对：2026-09-28
> 相关契约：[DataTable Runtime](../../addons/godo_framework/Runtime/DataTable/USAGE.md)、[DataTable Tool](../../addons/godo_framework/Tools/DataTable/USAGE.md)

## 1. 问题与目标

数据表需要同时满足策划可编辑、构建可复现、运行时强类型和 Client/Server 边界明确。直接在运行时解析 CSV、反射构造对象或使用动态字典，会把格式错误、性能成本和裁剪风险带入游戏。

DataTable 的目标是：

- 使用版本控制内的 Schema 作为字段和约束的唯一来源；
- 在 Editor、CLI 或 CI 中完成 CSV 校验和确定性生成；
- 生成强类型 C#、Manifest 和紧凑运行时数据；
- 运行时显式加载、事务发布、缓存和卸载；
- 保持 Native AOT、Trimming 和跨语言 Manifest 兼容；
- 让数据错误在构建期可见，不覆盖上一次成功产物。

## 2. 非目标

- 在游戏运行时解析 CSV、Excel 或 Google Sheets。
- 用反射、动态字典或运行时代码生成替代强类型代码。
- 网络同步协议、鉴权、下载、热更新、PCK/DLC 挂载或补丁回滚。
- 加密、数字签名或防篡改机制。
- 自动编写业务配置规则。
- 超大表分块和加载中无缝替换。

## 3. 已确认方案

### 编辑与 Schema

- 首版输入是 UTF-8 CSV；电子表格工具只负责导出 CSV。
- JSON 格式的 Schema 维护表 ID、字段、类型、约束、外键、Audience 和输出位置。
- CSV 只保留表头与数据，不复制字段元数据。
- Editor、CLI、CI 和导出门禁使用同一份 Schema。
- Google Sheets、Excel 直读等连接器只有出现真实需求后才独立设计。

### 离线生成

- 工具先解析并全量校验，再在内存中生成候选产物。
- 全部校验成功后才事务提交；失败不改变已有产物。
- 相同输入产生相同输出，未变化文件不改写，避免无意义重编译。
- 单表生成仍执行全量一致性检查，只缩小提交范围。
- 默认产物是 Manifest、未压缩 `.gdtb` 和聚合强类型 C#。
- 可读 IR、Debug JSON、字段说明和完整构建报告不是默认产物；有诊断需求时再单独立项。

### 运行时加载

- GoDoRuntime 只注册 `IDataTableService`，不自动加载业务数据。
- 业务通过生成门面显式加载数据集。
- 多表数据集逐表读取，全部成功后一次性发布；失败或取消不暴露半成品。
- 同一数据集不支持并发重复加载或加载中替换。
- 卸载只释放 Service 持有的引用，不强制销毁业务仍持有的表。
- 运行时不扫描程序集、不反射创建行类型，也不维护第二套资源缓存。

### Client / Server

- 表声明 Shared、ClientOnly 或 ServerOnly Audience。
- 目标 Manifest 只包含目标允许携带的表。
- Shared 摘要用于发现客户端与权威服务器的数据不一致。
- 摘要不是签名；网络握手、拒绝连接和补丁策略由游戏决定。
- 非 Godot 服务端优先消费同一次构建生成的 Server Manifest 或显式导出的规范化数据，不复制一套手工规则。

## 4. 格式、压缩与发布取舍

二进制格式和 Manifest 均带显式版本。读取器先验证格式、数据集、表和摘要，再构造字符串池、行数组与主键索引。

当前工具链生成未压缩候选。Zstd 的正式选择需要移动端和真实数据分布证据；在此之前不固化自动压缩阈值。压缩、加密和远程交付不得共享一个模糊开关。

Godot 导出插件负责目标过滤，但当前 Godot 4.x 的 EditorExportPlugin 不能可靠中止失败导出，因此正式发布必须通过已有包装脚本或统一发布门禁。精确命令维护在 Tool `USAGE.md`。

## 5. 生命周期、失败与性能

- 离线工具是一次性进程，不进入游戏运行时。
- Editor 扩展只在窗口操作或执行命令时工作，不常驻逐帧处理。
- Runtime API 只允许 Godot 主线程调用。
- 单表读取是同步完整解码；多表加载只在表边界让出 Process 帧并观察取消。
- 加载失败通过结构化异常保留数据集、表和阶段信息，不返回部分结果。
- Debugger 通过 internal 快照展示加载、发布和最近结果；Release 不保留诊断历史。

具体文件上限、支持类型、异常、命令、内存数字和回归证据由两份模块 `USAGE.md` 维护。

## 6. 剩余验证

离线编译、Editor 接入、Client/Server 过滤、可靠导出门禁、Runtime 事务加载、PCK 读取和 Windows ExportRelease 已有证据。提升成熟度前仍需：

- 移动平台和目标 RID 的加载、内存与 AOT 验证；
- 真实权威服务器消费 Manifest 的完整流程；
- 真实数据分布下是否需要 Zstd，以及对应解压成本；
- 真实项目对诊断产物和构建期自定义校验的需求。

当前成熟阶段以[模块状态](../00_项目/模块状态.md)为准。
