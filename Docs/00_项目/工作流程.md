# 工作流程

> 文档类型：工作流
> 状态：当前
> 权威范围：框架任务从开始到收尾的文档与验证流程
> 最近核对：2026-09-28
> 相关入口：[内部文档入口](../README.md)、[根协作规则](../../AGENTS.md)

## 1. 开始任务

1. 阅读[当前开发](当前开发.md)，确认任务属于当前阶段。
2. 按 [`Docs/README.md`](../README.md) 路由读取架构、模块 `USAGE.md` 或工作流。
3. 写清一个可验证的完成标准；多个独立目标拆开处理。
4. 检查工作区已有修改，保留并避开无关内容。

## 2. 判断是否需要设计或决策

- 只修正文档错误：直接依据源码和测试修正。
- 修改模块内部实现且外部行为不变：遵循模块 `USAGE.md` 和现有测试。
- 新增模块、改变 public API、生命周期、失败语义或依赖：先使用[设计模板](../_模板/设计文档模板.md)，并取得明确确认。
- 存在多个长期影响方案：登记到[待确认问题](待确认问题.md)；确认后追加[决策日志](决策日志.md)。

## 3. 实现与验证

1. 只修改完成目标所需的最小范围。
2. 先运行最贴近改动的低成本检查，再运行风险要求的回归、构建或 Godot 验证。
3. 测试结论只写已经执行的内容；未执行的人工验证单独列出。

## 4. 同步文档

| 变化 | 必须复核 |
|---|---|
| public API、失败语义、生命周期、性能 | 模块 `USAGE.md`、API Reference、公开手册覆盖状态 |
| 跨模块依赖或运行时入口 | 架构基线、决策日志 |
| 模块成熟阶段 | 模块状态、当前开发 |
| 未来顺序或候选方向 | 路线图、待确认问题 |
| 用户操作方式 | `PublicDocs/Manual/`、导航与翻译状态 |
| 新的 Godot/C# 已确认坑位 | `03_工作流/Godot问题记录.md` |

## 5. 收尾

- 检查 diff 和无效链接，确认没有顺带改动。
- 汇报修改文件、核心思路、验证结果和未处理风险。
- 当前主要目标或模块阶段发生变化时，更新当前开发和模块状态；普通小修不制造进度噪音。
