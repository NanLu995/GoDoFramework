以下日期为迁移登记日期；原始决定日期未单独记录。改变决定时新增记录并注明“替代 DEC-xxx”。

## DEC-001：框架只提供跨游戏机制

- 登记日期：2026-09-25
- 状态：生效
- 决定：`GoDo.*` 不包含角色、战斗、任务等具体玩法概念。
- 理由：保持跨项目复用，避免框架反向依赖业务。

## DEC-002：GoDoRuntime 是唯一 Autoload 入口

- 登记日期：2026-09-25
- 状态：生效
- 决定：运行时初始化、长期服务注册和退出清理由 `GoDoRuntime` 统一承担；业务流程不进入该入口。
- 理由：避免重复初始化和隐式生命周期。

## DEC-003：依赖整体向下，ErrorHub 是唯一全局直连例外

- 登记日期：2026-09-25
- 状态：生效
- 决定：Core 不借助 Services 横向耦合；跨层事实优先通过 EventChannel；ErrorHub 因全局错误上报职责允许直接访问。
- 理由：保持依赖可见，同时避免错误处理形成循环。

## DEC-004：模块契约就近维护

- 登记日期：2026-09-25
- 状态：生效
- 决定：模块 `USAGE.md` 是 API、失败语义、生命周期、性能和验证证据的详细来源。
- 理由：减少项目级文档和实现之间的重复与漂移。

## DEC-005：内部与公开文档分离

- 登记日期：2026-09-25
- 状态：生效
- 决定：`Docs/` 管理项目内部事实、计划、设计和研究；`PublicDocs/` 只管理对外手册与 API Reference。
- 理由：让使用者文档保持任务导向，同时让维护资料可以准确记录状态和取舍。

## DEC-006：Services 不是框架内部依赖捷径

- 登记日期：2026-09-25
- 状态：生效
- 决定：Services 只供业务层访问长期服务；框架内部协作必须使用显式依赖或事件。
- 理由：避免 Service Locator 隐藏依赖和生命周期。

## DEC-007：ResourceHub 保持 Godot Resource 边界

- 登记日期：2026-09-25
- 状态：生效
- 决定：ResourceHub 不承担远程下载、PCK/DLC、热更新、目录加载或第二套缓存。
- 理由：这些能力的生命周期和失败模型不同，应在真实需求出现时独立设计。

## DEC-008：运行时代码必须兼容 Native AOT 与 Trimming

- 登记日期：2026-09-25
- 状态：生效
- 决定：运行时序列化使用源生成元数据或调用方显式元数据，不以反射扫描和动态程序集加载作为默认机制。
- 理由：框架不能把裁剪和 AOT 风险转嫁给消费项目。
