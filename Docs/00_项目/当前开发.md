## 当前阶段

框架主要能力已经完成首版建设，当前处于**基线收敛与真实项目验证**阶段。工业级定位是长期质量标准，不是继续扩张模块数量的理由。

## 主要目标

用真实游戏开发、干净项目安装和发布门禁继续验证现有模块，发现重复出现的缺口后再单独立项；当前不新增泛化框架层。

## 下一步

1. 持续记录 Scheduler、Input、DataTable、Audio、Camera 等首版能力在真实项目和目标平台上的证据。
2. 在出现明确业务输入后，分别评估第二视角输出、2D 空间音频或资源扩展，不预先合并为大模块。
3. 在准备下一次对外发布时复核版本号、发布说明、历史升级证据和发布包验收结果。

## 最近完成的验证

- 2026-09-28 使用 Godot 4.7.2 Mono 在 Windows 完成统一发布门禁：核心与可选集成回归、Demo3D、DataTable 编辑器导出与 ExportRelease、文档、API 兼容检查和四类发布包均通过。
- 核心 ZIP 已在临时干净项目中完成安装、重复安装、完整替换升级、冲突保护、安全卸载和宿主移除验证，具体边界见[发布工具](../../release/README.md)。
- 2026-09-28 使用真实 `v0.7.0` 标签包写入系统 Settings 和 Save 容器数据，完整替换为 `v0.8.0` 后成功读取原值与业务版本号；该证据不代替各游戏业务 Codec 自己的数据结构迁移测试，Android、iOS 与其他目标 RID 也未由本轮覆盖。
- 工作区 Release 编译仍报告 GUIDE 与 Phantom Camera 第三方源码的 5 项警告；核心包及自有代码没有因此新增失败，但下一次对外发布前仍需复核第三方版本或上游修复状态。

## 持续验证

- Windows 以外平台、移动端与目标 RID 的行为和性能。
- 首版 public API 在真实项目中的可用性与迁移成本。
- 干净项目安装、完整替换升级、安全移除和导出产物边界。

## 阻塞与待确认

当前没有阻塞框架基线收敛的已知问题。需要产品或场景输入的事项集中记录在[待确认问题](待确认问题.md)。

## 本阶段不做

- 不建设 ECS、依赖注入容器、通用协程框架或另一套场景系统。
- 不因外部框架已有某个模块就直接扩大 GoDo 范围。
- 不把远程资源、PCK/DLC、热更新或高级缓存塞入 ResourceHub。
